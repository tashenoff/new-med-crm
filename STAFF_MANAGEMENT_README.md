# Система управления персоналом

## Обзор

Система управления персоналом предназначена для управления сотрудниками клиники с гибкой системой ролей и прав доступа.

## Роли персонала

### 1. Супер Администратор (`super_admin`)
- **Полный доступ** ко всем функциям системы
- Управление всеми разделами без ограничений
- Управление персоналом, включая других администраторов

### 2. Администратор (`admin`)
- Управление пациентами (просмотр, редактирование, удаление)
- Управление врачами (просмотр, редактирование)
- Доступ к календарю и записям
- Управление CRM
- Управление складом
- Доступ к справочникам
- Просмотр финансов и статистики
- Просмотр персонала

### 3. Врач (`doctor`)
- Просмотр и редактирование пациентов
- Доступ к календарю и записям
- Просмотр справочников
- Просмотр статистики

### 4. Маркетолог (`marketer`)
- Просмотр пациентов
- Полный доступ к CRM
- Просмотр статистики

### 5. Администратор клиники (`administrator`)
- Просмотр пациентов
- Доступ к календарю и записям
- Просмотр справочников

## Права доступа

### Пациенты
- `patients_view` - Просмотр списка пациентов
- `patients_edit` - Редактирование данных пациентов
- `patients_delete` - Удаление пациентов

### Врачи
- `doctors_view` - Просмотр списка врачей
- `doctors_edit` - Редактирование данных врачей
- `doctors_delete` - Удаление врачей

### Календарь
- `calendar_view` - Просмотр календаря
- `calendar_edit` - Создание/изменение записей

### CRM
- `crm_view` - Просмотр CRM данных
- `crm_edit` - Управление CRM

### Склад
- `warehouse_view` - Просмотр склада
- `warehouse_edit` - Управление складом

### Справочники
- `directory_view` - Просмотр справочников
- `directory_edit` - Редактирование справочников

### Финансы
- `finance_view` - Просмотр финансовой информации
- `finance_edit` - Управление финансами

### Статистика
- `statistics_view` - Просмотр статистики

### Персонал
- `staff_view` - Просмотр списка персонала
- `staff_edit` - Редактирование данных персонала
- `staff_delete` - Удаление персонала

### Системные
- `system_settings` - Доступ к системным настройкам

## Backend API

### Эндпоинты

#### GET `/api/staff/`
Получить список всего персонала
- **Требуется**: роль `admin` или `super_admin`
- **Параметры**: 
  - `skip` (опционально): пропустить записи
  - `limit` (опционально): лимит записей

#### GET `/api/staff/{staff_id}`
Получить информацию о сотруднике
- **Требуется**: роль `admin` или `super_admin`

#### POST `/api/staff/`
Создать нового сотрудника
- **Требуется**: роль `admin` или `super_admin`
- **Тело запроса**:
```json
{
  "email": "user@example.com",
  "password": "securepassword",
  "full_name": "Иванов Иван Иванович",
  "role": "doctor",
  "phone": "+7 (777) 123-45-67",
  "custom_permissions": []
}
```

#### PUT `/api/staff/{staff_id}`
Обновить данные сотрудника
- **Требуется**: роль `admin` или `super_admin`

#### DELETE `/api/staff/{staff_id}`
Удалить сотрудника (мягкое удаление)
- **Требуется**: роль `admin` или `super_admin`
- **Примечание**: Нельзя удалить свой собственный аккаунт

#### GET `/api/staff/{staff_id}/permissions`
Получить список прав сотрудника
- **Доступно**: для себя или для admin/super_admin

#### GET `/api/staff/roles/permissions/{role}`
Получить список прав для конкретной роли
- **Доступно**: всем авторизованным пользователям

## Безопасность

### Хеширование паролей
Пароли хешируются с использованием `bcrypt` перед сохранением в базу данных.

### Авторизация
Все эндпоинты защищены JWT токенами. Для доступа к управлению персоналом требуется роль администратора.

### Защита от самоудаления
Система не позволяет администратору удалить свой собственный аккаунт.

## База данных

### Коллекция `staff`
Хранит информацию о сотрудниках:
- `_id` - уникальный идентификатор
- `email` - email для входа в систему
- `full_name` - полное имя
- `role` - роль сотрудника
- `phone` - телефон (опционально)
- `is_active` - активен ли сотрудник
- `hashed_password` - хешированный пароль
- `custom_permissions` - дополнительные права
- `created_at` - дата создания
- `updated_at` - дата обновления
- `last_login` - дата последнего входа

### Коллекция `users`
При создании сотрудника автоматически создается запись в коллекции `users` для авторизации в системе.

## Примеры использования

### Создание нового врача
```python
import requests

url = "http://localhost:8001/api/staff/"
headers = {
    "Authorization": "Bearer YOUR_TOKEN",
    "Content-Type": "application/json"
}
data = {
    "email": "doctor@clinic.com",
    "password": "SecurePassword123!",
    "full_name": "Петров Петр Петрович",
    "role": "doctor",
    "phone": "+7 (777) 999-88-77"
}

response = requests.post(url, json=data, headers=headers)
print(response.json())
```

### Получение списка персонала
```javascript
const API = process.env.REACT_APP_BACKEND_URL;
const token = localStorage.getItem('token');

const response = await fetch(`${API}/api/staff/`, {
  headers: {
    'Authorization': `Bearer ${token}`,
    'Content-Type': 'application/json'
  }
});

const staff = await response.json();
console.log(staff);
```
