# Локальный пакет CRM: источники и воронка

Основа frontend: main `068e82881e8b0c81fac924c63085408d2ae5055b` с сохранённым обновлением consent. Основа backend: ref-2 `f5f73dc460be16e082f7518cca532f0acbbf7674`. Пакет не опубликован.

## Карточка обращения

Для входящих телефонных карточек техническое описание `Обращение через Zadarma-звонок` заменяется представлением `Обращение через «Название источника»`. Имя читается по сохранённому `source_id` из справочника, затем из сохранённого `source_name`. Дублирующий источник под именем убран только у таких карточек. Произвольные заметки и остальные каналы сохраняются.

При отсутствии имени и наличии ID: `Обращение по телефону — источник недоступен`. Без ID: `Обращение по телефону — источник не указан`. Тип канала и провайдер не выдаются за имя источника. Данные карточки не переписываются.

## Воронка и сравнение

- Воронка использует канонические карточки и колонки канбана в его порядке. Существующие определения показателей `salesFunnel` сохранены.
- Общий период — дата первого касания (`created_at`), с существующей логикой локальных календарных дат и включительными границами. По умолчанию все даты.
- Режим «По этапам» дополнительно фильтруется по конкретному `source_id`.
- «Сравнение источников» использует все источники за этот же период независимо от dropdown режима этапов. Источники показаны строками таблицы, не стадиями процесса.
- Показатели: количество канонических карточек; текущий статус `converted` («Пациент пришёл»); его доля от всех карточек строки; потери `rejected + lost`; в обработке `new + in_progress + contacted + qualified`. `closed` не добавляется к конвертированным. При нулевом знаменателе конверсия — `—`. Выручка и дополнительные визиты не рассчитываются.
- Справочник включает строки с нулями. Отсутствующий ID и ID вне справочника сгруппированы отдельно: «Источник не указан», «Источник недоступен». Итог строится из той же коллекции, связанные повторные обращения повторно не считаются.
- Чекбоксы «Видимые этапы» влияют только на представление. Итоги, доли, масштаб полос и отношения соседних этапов используют полный набор. Если предыдущий этап скрыт, это подписано. Отношения текущих количеств не являются восстановленной историей переходов.
- Локальная настройка хранит скрытые ID с областью пользователь + клиника; без идентификатора клиники используется область текущей установки (localStorage дополнительно ограничен origin). Без идентификатора пользователя настройка не сохраняется. Новые этапы видны; устаревшие ID игнорируются. Скрыть всё разрешено с явным пустым состоянием и кнопками показать всё / сбросить.

## Источник при записи

Общая форма `AppointmentModal` использует существующий справочник с пагинацией. Начальный конкретный источник обращения имеет приоритет. Без контекста обращения берётся сохранённый `source_id` выбранного пациента. Если краткая карточка пациента его не содержит, читается `/api/patients/{id}`. Произвольный поиск источника по другим обращениям не выполняется.

WhatsApp читает конкретное связанное обращение по `linked_lead_id`; `source: patient/lead` в модели чата не является каналом привлечения. Неизвестный или удалённый источник оставляет явный выбор. Смена пациента очищает старое значение и источник прежнего контекста. Запоздалые ответы и повторная загрузка не перетирают ручной выбор, включая пустой выбор. Редактирование существующей записи сохраняет её источник.

CRM и WhatsApp передают выбранный `source_id` в `schedule-appointment`. Backend проверяет переданный ID по справочнику, берёт тип из этого же источника и сохраняет в новой записи. При отсутствии нового поля старый API-контракт сохраняется. Исторический источник существующего пациента и обращения не меняется. Создание пациента из CRM сохраняет прежнюю логику наследования источника обращения.

## Проверка и пересечения

Моки и искусственные данные: UI-тесты карточек/воронки/общей формы/реальных callback CRM и WhatsApp; backend mock-only тесты сохранения и прежней телефонии; браузер реального приложения на отдельном localhost-порту и в отдельном Chrome-контексте; desktop 1440 и mobile 390. Любые `/api/` запросы браузера перехватываются, внешние запросы блокируются. Проверены точные итоги, нули, неизвестные ID, длинные имена, скрытие/повторное открытие/перестановка/добавление этапов, ручной выбор и гонки ответов.

Общие файлы для будущей интеграции: `EnhancedLeadsView.js`, `WhatsAppInbox.jsx`, `AppointmentModal.js`, backend `crm/routes/leads.py`. Guards, публичные consent-маршруты, `PatientTermsStatus.jsx` и `patientTerms.css` пакет не меняет. Последние два файла и тесты consent сохранены из main. Публикация требует отдельного согласования готового пакета.
